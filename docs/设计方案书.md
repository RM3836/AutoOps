# AutoOps 项目设计方案书

## 一、选题背景

随着企业数字化转型加速，服务器数量快速增长。传统人工运维方式存在效率低、故障发现滞后、安全隐患难预警等问题。本项目设计并实现一套企业级智能自动化运维平台，通过自动化监控、远程运维、日志分析和智能告警，提升运维效率和系统安全性。

## 二、需求分析

### 2.1 功能需求
- **系统监控**：CPU/内存/磁盘/网络/进程实时采集与展示
- **服务器详情**：CPU型号核心、内存Buffers/Cache、磁盘分区Inode、网卡流量、磁盘IO
- **SSH远程运维**：远程登录、命令执行、文件传输、多服务器管理
- **日志管理**：日志采集、异常检测、暴力破解识别、IP聚合分析
- **自动告警**：阈值告警、邮件通知、Web页面提示
- **Web可视化**：仪表盘、图表、暗色主题
- **运维工具箱**：主机扫描、并行端口扫描、DNS解析(A/MX/NS)、进程管理、报告下载

### 2.2 非功能需求
- 响应时间 < 2秒
- 支持多服务器并行管理
- 数据存储稳定可靠（SQLite）
- 界面美观，暗色主题适合长时间监控

## 三、技术选型

| 技术 | 版本 | 选型理由 |
|------|------|----------|
| Python | 3.10+ | 课程主语言，生态丰富 |
| Flask | 3.0 | 轻量级Web框架，适合中小型项目 |
| SQLite | 3 | 零配置嵌入式数据库，部署简单 |
| psutil | 5.9 | 跨平台系统监控库，功能全面 |
| Paramiko | 3.4 | Python SSH库，支持密码/密钥认证 |
| schedule | 1.2 | 轻量级定时任务库，API简洁 |
| Bootstrap | 5.3 | 响应式前端框架，开发效率高 |
| Chart.js | 4.4 | 轻量级图表库，支持实时更新 |

## 四、模块划分

```
┌──────────────────────────────────────┐
│           Flask Web层                │  路由 + 模板 + API + send_file
├──────┬──────┬──────┬──────┬──────────┤
│ 仪表 │ 服务 │ SSH  │ 日志 │  告警    │  业务逻辑层
│ 盘   │ 器   │      │ 分析 │          │
├──────┴──────┴──────┴──────┴──────────┤
│         SQLite 数据层                │  数据持久化
└──────────────────────────────────────┘
```

### 模块职责：
1. **monitor/** - 使用psutil采集系统指标（CPU/内存/磁盘/网卡/IO 5维度）
2. **remote/** - 使用Paramiko实现SSH运维（密钥认证+批量执行）
3. **security/** - 日志分析与安全检测（关键词+正则+IP聚合三层）
4. **alert/** - 阈值检测与多渠道告警（Web+邮件+日志）
5. **tools/** - 运维工具箱（主机扫描/并行端口扫描/DNS/进程管理/报告导出）

## 六、测试方案

### 6.1 功能测试
- 仪表盘数据刷新测试
- SSH连接与命令执行测试
- 告警触发测试（制造CPU高占用）
- 日志分析功能测试
- 工具箱各功能测试

### 6.2 异常测试
- SSH连接失败（网络不通）
- 数据库损坏恢复
- 大量并发请求
- 无效输入处理

### 6.3 性能测试
- 监控采集间隔精度
- 页面响应时间
- 数据库查询效率
